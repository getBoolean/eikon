# Stage 7: A 64-bit Windows program returns 42

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An original amd64 Windows program returns 42. Unity's player and the amd64 `Game.exe` builds need this CPU path before they need Direct3D 11.

**Architecture:** The same native ARM64 Wine process loads Box64's amd64 CPU DLL. Autorun calls that DLL `winebox64ec` and connects it through ARM64EC. This stage uses Box64's WowBox64 amd64 support at tag `v0.3.6` when the build produces it, and otherwise stops with a written gap in `plans/amd64-gap.md` instead of inventing an ARM64EC layer. Stage 6's 32-bit path stays in place.

**Tech Stack:** Wine `wine-11.0` `--enable-archs=aarch64,i386,x86_64`, Box64 `v0.3.6`, mingw-w64 `x86_64`.

## Global Constraints

- Linux guests stay on FEX. This stage is Windows amd64 only.
- The guest is `demos/windows/amd64`.
- No Direct3D in this stage. Stage 8 owns the first Direct3D 11 frame.
- No JIT bypass. Stage 3's `add42=42` is required for a device claim.
- No program titles.

### Task 1: The guest

**Files:**
- Create: `demos/windows/amd64/main.c`
- Test: `tests/test_amd64_guest.py`

**Interfaces:**
- Consumes: nothing
- Produces: `amd64.exe` whose `main` returns 42

- [ ] **Step 1: Write the program**

```c
int main(void) {
    return 42;
}
```

Build: `x86_64-w64-mingw32-gcc -O2 -o amd64.exe main.c`

Confirm with `objdump -f` that the machine is `x86-64`. Desktop Wine exits 42.

- [ ] **Step 2: Commit**

```bash
git add demos/windows/amd64 tests/test_amd64_guest.py
git commit -m "Add the amd64 guest that returns 42."
```

### Task 2: Load it

**Files:**
- Create: `docs/build-wine-amd64.md`
- Create: `plans/amd64-gap.md` only if the Box64 tag cannot produce the CPU DLL

**Interfaces:**
- Consumes: stage 4's Darwin `ntdll` for process exit
- Produces: probe log `amd64=42`

- [ ] **Step 1: Ask the Box64 build for the amd64 CPU DLL**

```bash
cmake -S third_party/box64 -B build/box64-amd64 -DWOW64=ON -DARM_DYNAREC=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build/box64-amd64 -j4
```

Record the DLL path in `docs/build-wine-amd64.md`. If the tag's WowBox64 output is only the i386 `wowbox64.dll`, write `plans/amd64-gap.md` with that fact and stop. Do not start an ARM64EC port inside this task.

- [ ] **Step 2: Device run when the DLL exists**

Button `Run amd64`. Expected log: `amd64=42`.

- [ ] **Step 3: Commit**

```bash
git add docs/build-wine-amd64.md Makefile
git commit -m "Run the amd64 guest through the Box64 CPU DLL."
```
