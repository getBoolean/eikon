# Stage 3: Box64 runs one x86 function

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 32-bit x86 function that returns `42` does so inside the Eikon process, using Box64's ARM64 dynarec and the code memory stage 2 already measured.

**Architecture:** Box64 is a submodule pinned at tag `v0.3.6`. Eikon does not edit the submodule. The iOS-specific code arena lives in this repo and is the only file allowed to call `pthread_jit_write_protect_np` or `mprotect` for translated code. If `plans/probe-result.md` says `jit_run=skip`, this stage builds the library and the test harness, then stops. It does not invent a way to get JIT.

**Tech Stack:** Box64 `v0.3.6`, C, Theos, CMake for a host ARM64 Linux build of the same blob.

## Global Constraints

- Pin `third_party/box64` at `v0.3.6`.
- Box64 is the Windows CPU backend only. Linux guests stay on FEX.
- No JIT bypass. The arena returns an error when the probe said `skip`.
- No program titles.

### Task 2: Run the blob on a Linux ARM64 host

**Files:**
- Create: `tests/host/test_add42_box64.c`

**Interfaces:**
- Consumes: `kAdd42`
- Produces: exit code 0 when Box64's interpreter returns 42 from that blob

- [ ] **Step 1: Build upstream Box64 on Linux ARM64**

```bash
cmake -S third_party/box64 -B build/box64-host -DARM_DYNAREC=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build/box64-host -j4
```

Expected: `build/box64-host/box64` exists.

- [ ] **Step 2: Assemble the blob into an ELF the interpreter can enter**

`tests/host/test_add42_box64.c` is a native harness only if Box64 is linked as a library. `v0.3.6` does not offer a supported library entry for an arbitrary byte buffer. The host check is therefore a Linux i386 ELF, assembled on a machine with `nasm` and `gcc -m32`, containing one exported `add42` that is those nine bytes, run as:

```bash
box64 ./add42-elf ; echo $?
```

with the ELF's `_start` calling `add42` and exiting with its return value.

Expected: `42`

This host check proves the bytes. It does not prove the iOS arena.

- [ ] **Step 3: Commit the harness**

```bash
git add tests/host/test_add42_box64.c
git commit -m "Check the add-42 blob under Box64 on Linux."
```

### Task 3: iOS code arena

**Files:**
- Create: `src/guest/EikonCodeArena.h`
- Create: `src/guest/EikonCodeArena.m`

**Interfaces:**
- Consumes: `plans/probe-result.md` `jit_run`
- Produces:

```objc
typedef struct {
    void *rx;
    size_t size;
} EikonCodeBlock;

// Returns 0 on success. Returns ENOTSUP when probe jit_run was skip.
int EikonCodeArenaMap(const uint8_t *bytes, size_t len, EikonCodeBlock *out);
void EikonCodeArenaUnmap(EikonCodeBlock block);
```

- [ ] **Step 1: Implement the arena**

`EikonCodeArenaMap` copies `bytes` into a page obtained the same way as `RunCodeMemoryProbe`: `MAP_JIT` when that flag exists, write the bytes while write-protect is off, clear the instruction cache, then `mprotect` to `PROT_READ | PROT_EXEC`. If the probe file contains `jit_run=skip`, return `ENOTSUP` without calling `mmap`.

- [ ] **Step 2: Commit**

```bash
git add src/guest/EikonCodeArena.h src/guest/EikonCodeArena.m Makefile
git commit -m "Add the iOS code arena gated on the probe result."
```

### Task 4: Call the blob through Box64 on device

**Files:**
- Create: `src/guest/RunAdd42.h`
- Create: `src/guest/RunAdd42.m`
- Modify: `src/RootViewController.m`

**Interfaces:**
- Consumes: `EikonCodeArenaMap`, Box64 dynarec built with `-DARM_DYNAREC=ON` and `-DBOX32=ON`
- Produces: a button `Run add 42` that appends `add42=<n>` to `probe.log`

- [ ] **Step 1: Build Box64 for the iOS SDK**

Box64's Linux loader does not link into an iOS app. Build only the dynarec objects needed to translate `kAdd42`, with an iOS toolchain file `cmake/ios.toolchain.cmake` that sets `CMAKE_SYSTEM_NAME` to `iOS` and `CMAKE_OSX_ARCHITECTURES` to `arm64`. The first compile will fail on Linux-only files. Disable those files in the CMake invocation with the upstream options that turn off the interpreter's Linux loader usage for this target, and keep a list in `plans/box64-ios-omissions.md` of every file excluded and why. Do not patch files inside `third_party/box64`. Wrappers live under `src/guest/box64/`.

- [ ] **Step 2: Translate and call**

`RunAdd42` asks Box64 to translate `kAdd42` into the arena and calls the resulting function pointer. Append `add42=` and the decimal result.

- [ ] **Step 3: On device**

Expected log line: `add42=42`

If the probe said `skip`, the button appends `add42=unsupported` and the stage is done.

- [ ] **Step 4: Commit**

```bash
git add src/guest cmake plans/box64-ios-omissions.md Makefile
git commit -m "Run the add-42 blob through Box64 on iOS."
```
