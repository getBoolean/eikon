# Code Review: Section 07 - JIT controller

No high-confidence defects. The controller, seams, store, tests, and app wiring match section 07, including the iOS 15 floor (NSLock, ObservableObject, JITClock, Task.sleep(nanoseconds:); no Mutex, OSAllocatedUnfairLock, @Observable, or Swift Clock).

Request and probe behavior is right. gatherFacts re-detects the install, records CS_DEBUGGED as atLaunch or never, asks LiveJITSystem for TXM, consumes the sentinel, and probes only through JITPolicy.mayProbe. runProbeIfAllowed leaves a passed probe alone, skips with a short detail when the policy refuses, and on an allowed probe arms the sentinel, calls system.probe(), then disarms. If arm throws, it does not probe. The live system maps eikon_cs_flags with EIKON_CS_DEBUGGED (0x10000000) and treats errors as not debugged; on device it passes eikon_txm_firmware_present() into JITPolicy.txmInfo and maps eikon_jit_probe() through ProbeOutcome; in the simulator it reports TXM absent / not enforced and returns probe notRun without calling the C probe. Install detection already forces the simulator method, so mayProbe is false and the reason is simulator.

The TrollStore flow matches the plan. The first sceneBecameActive either starts one request or, when cooldown blocks a TrollStore/Lite install that still has no CS_DEBUGGED, publishes timedOut so Retry JIT can appear. Later activations do not open another URL. An in-flight request is single-flight (requestTask); recheck bails while it runs, so a foreground return cannot bounce. The URL is apple-magnifier / enable-jit / bundle-id from the injected runtime id; a nil id is an immediate timeout. Open failure publishes trollStoreTimedOut without sleeping. Otherwise the loop waits on the clock (10s deadline, 200ms poll) regardless of scene phase, and success sets csDebuggedSeen to afterTrollStoreRequest, sleeps the 300ms grace period, probes, clears the request, and lets JITPolicy attribute source trollStore. Timeout clears isRequestingTrollStoreJIT. retryTrollStoreJIT ignores cooldown only when manual and no request is in flight, and still records the attempt with synchronize(). retryProbe clears the sentinel block and a failed/not-run outcome, keeps the earliest seen time or sets onForeground if the flag is newly set, and probes again under the sentinel. JITStatusStore.shared.current is an NSLock snapshot; every publish goes through JITPolicy.status and store.update. Init publishes placeholder and does not probe or open a URL. EikonApp calls gatherFacts in init, holds the shared controller as an ObservedObject, injects it into StatusView, and forwards scenePhase == .active. The five tests use fakes, a private store, a temp sentinel, and a suite UserDefaults, and they do not touch the singletons.

The plan’s simulator done-check (first .active reaches the controller, reason simulator, no URL) is still a manual run; the wiring for it is in place.
